Kernel API

由 core/include/dnsk_core.h、dnsk_abi.h 及各 layout 头文件的 kernel-doc 注释生成。权威定义始终是头文件本身；本页与头文件不一致时 以头文件为准。

DNSK_CORE_MAGIC

identifies a valid struct dnsk_core_api

**Description**

Feature modules compare this value against the **magic** field before using any function pointer from the API, so that an unrelated struct returned by a stale or replaced core is rejected instead of dereferenced.

DNSK_CORE_ABI

ABI revision of struct dnsk_core_api

**Description**

Passed by the feature module to dnsk_core_get(). The core refuses the request unless the caller's value matches exactly; the value changes whenever the layout or semantics of the API change.

DNSK_FEATURE_NAME_LEN

maximum feature name including the NUL

**Description**

dnsk_feature_add() rejects a longer name with -ENAMETOOLONG. Names are stored by value, the caller's string need not stay alive.

DNSK_HOOK_KEY_LEN

maximum hook key including the NUL

**Description**

A key at or above this length is rejected with -EINVAL by dnsk_hook_add(). The key is copied into the hook registry and is what dnsk_hook_del() later uses to identify the hook.

dnsk_status

implementation level reported for a feature

**Constants**

``DNSK_STATUS_UNKNOWN`` value zero, no level claimed.

This is the value a zeroed structure holds; it is not a level. It also is what dnsk_status_name() returns "unknown" for.

``DNSK_STATUS_NOT_SHIPPED`` not built or not yet usable.

``DNSK_STATUS_FEASIBILITY`` under a feasibility gate, no contract yet.

``DNSK_STATUS_DEVELOPMENT`` implemented, acceptance not complete.

``DNSK_STATUS_NATIVE`` N, the host already has it, or it matches the AOSP Native oracle over the full acceptance matrix.

``DNSK_STATUS_REAL`` R, ported from source of the same KMI, the diff is auditable and the workload passes.

``DNSK_STATUS_DIFFERENTIAL`` D, parity with the AOSP Native oracle inside the defined contract.

``DNSK_STATUS_VIRTUAL`` V, real state, enforcement and files, but not a native kernel cgroup_subsys.

``DNSK_STATUS_NA`` the feature does not exist upstream for this KMI.

``DNSK_STATUS_UNSUPPORTED`` this KMI does not support the feature.

The level a feature module claims in :c:type:`struct dnsk_feature_desc <dnsk_feature_desc>`. It is informational: core stores it and prints it through the diag interface, it does not change how the feature behaves. The single letters in the field descriptions match the levels defined in the project status document.

dnsk_hook_type

kind of hook requested from the core

**Constants**

``DNSK_HOOK_KPROBE`` kprobe on **symbol**.

**replacement** is the pre-handler, typed ``int (*)(struct kprobe *, struct pt_regs *)``; returning non-zero skips the probed instruction. **original_out** receives the probed address, not a function pointer.

``DNSK_HOOK_SYSCALL`` replace the sys_call_table slot of **syscall_nr**.

**replacement** is the new syscall body, **original_out** receives the slot value that was there before. Fails with -EOPNOTSUPP when the patching backend is unavailable, and the slot must not be NULL.

``DNSK_HOOK_DATA`` replace a pointer stored at **target**.

**target** points at the pointer slot to overwrite, **replacement** is the new value. The old value, which may legitimately be NULL, is recorded and written back by dnsk_hook_del().

``DNSK_HOOK_KRETPROBE`` kretprobe on **symbol**.

**target** is the entry handler and **replacement** is the return handler, both typed ``int (*)(struct kretprobe_instance *, struct pt_regs *)``. The return value is read with regs_return_value() from the return handler's **regs**.

Selects which fields of :c:type:`struct dnsk_hook_req <dnsk_hook_req>` are meaningful and how core installs and removes the hook. Core owns every hook it installs, so a feature module cannot leave a permanent hook behind on unload.

dnsk_hook_req

one hook registration request

**Definition**::

struct dnsk_hook_req { const char *key; enum dnsk_hook_type type; struct module *owner; const char *symbol; unsigned int syscall_nr; void *target; void *replacement; void **original_out; };

**Members**

``key`` unique name of the hook, shorter than DNSK_HOOK_KEY_LEN.

``type`` which kind of hook to install.

``owner`` registering module, for diagnostics.

Core does not pin it. The owner must remove every hook in module_exit().

``symbol`` kernel symbol name for ``DNSK_HOOK_KPROBE`` and ``DNSK_HOOK_KRETPROBE``, unused otherwise.

``syscall_nr`` sys_call_table index for ``DNSK_HOOK_SYSCALL``.

``target`` kretprobe entry handler, or the pointer slot to patch for ``DNSK_HOOK_DATA``.

``replacement`` handler or value to install.

``original_out`` optional out-parameter.

Receives the value displaced by the hook; may be ``NULL`` when the caller does not need it.

Passed to dnsk_hook_add(), which copies or records what it needs; the strings must stay valid only for the duration of the call. Which fields are required depends on **type**. Core does not pin **owner**, so the registering module must remove every hook it added in module_exit(); the reference the module holds on core through dnsk_core_get() keeps core itself alive until then.

dnsk_feature_desc

one feature registration request

**Definition**::

struct dnsk_feature_desc { const char *name; const char *version; enum dnsk_status status; const char *caps; struct module *owner; };

**Members**

``name`` unique feature name, shorter than DNSK_FEATURE_NAME_LEN.

``version`` optional version string, may be ``NULL``.

``status`` implementation level claimed by the feature.

``caps`` optional capabilities string, may be ``NULL``.

``owner`` registering module, for diagnostics.

Core does not pin it. The owner must remove its registration in module_exit().

Passed to dnsk_feature_add(), which copies every string; the caller's buffers do not need to outlive the call. Registrations are informational, they do not enable or install anything.

dnsk_core_api

function table returned by dnsk_core_get()

**Definition**::

struct dnsk_core_api { u32 magic; u16 abi; u16 size; void *(*resolve)(const char *name); int (*hook_add)(const struct dnsk_hook_req *req); int (*hook_del)(const char *key); int (*feature_add)(const struct dnsk_feature_desc *desc); int (*feature_del)(const char *name); void (*log)(int level, const char *fmt, ...); int (*patch_pointer)(void *target, void *value); struct module *owner; };

**Members**

``magic`` must equal DNSK_CORE_MAGIC.

``abi`` must equal the DNSK_CORE_ABI the caller was built against.

``size`` size of this structure in bytes.

``resolve`` look up a kernel symbol by name.

**name**: symbol name, e.g. ``"sys_call_table"``.

Resolves through kallsyms at runtime, so core imports no non-exported symbol itself. On kernels before 6.1 a direct lookup that fails is retried against the KCFI ``<name>.cfi_jt`` jump table entry.

Return: the symbol address, or ``NULL`` when it cannot be resolved.

``hook_add`` install a hook owned by core.

**req**: the hook to install.

Return: ``0`` on success, negative errno on failure, including -EINVAL for a malformed request, -EBUSY for a duplicate **key**, -ENOSPC when the registry is full, and -EOPNOTSUPP when the patching backend is not available.

``hook_del`` remove a hook by key and restore what it replaced.

**key**: the key the hook was added with.

Restores whatever the hook displaced, then waits for an RCU grace period on success, so a caller may free its handler data on return.

Return: ``0`` on success, -EINVAL for a ``NULL`` **key**, -ENOENT when no hook has that key, or the error from restoring the original.

``feature_add`` record a feature registration.

**desc**: the registration to record.

Return: ``0`` on success, -EINVAL for a missing **name**, **owner** or empty name, -ENAMETOOLONG for an over-long name, -EEXIST when the name is taken, or -ENOSPC when the registry is full.

``feature_del`` drop a feature registration by name.

**name**: the name the feature was registered with.

Return: ``0`` on success, -EINVAL for a ``NULL`` **name**, or -ENOENT when no feature has that name.

``log`` formatted log line through the core logger.

**level**: log level; 0 logs an error, 1 a warning, any other value logs info. **fmt**: printf-style format, rendered into a 256-byte stack buffer and therefore truncated past that; a ``NULL`` **fmt** logs nothing. **...**: arguments for **fmt**.

Context: Any context. The line is emitted through printk, so the usual printk rules apply.

``patch_pointer`` write an aligned pointer into kernel memory.

**target**: address of the pointer slot to write. **value**: pointer value to store.

Uses the patching backend (stop_machine + fixmap), not a plain store, so the target may live in read-only-after-init memory.

Return: ``0`` on success, -EINVAL for a ``NULL`` **target**, or -EOPNOTSUPP when the patching backend is not available.

``owner`` the core module, with one reference held for the caller.

dnsk_core_get() returns with one reference taken on this module. The caller must keep it for as long as the API may be used and release it with module_put(owner); the API must not be touched after that final put.

The core fills this once at init and hands out a pointer to it. A caller must validate **magic** and **abi** before dereferencing any function pointer; dnsk_core_get() already does both, so they are only needed if the structure is reached by other means.

dnsk_core_get

obtain the core API function table

``u16 abi`` ABI revision the caller was built against, normally DNSK_CORE_ABI.

``u16 size`` size of the caller's :c:type:`struct dnsk_core_api <dnsk_core_api>`, normally sizeof().

**Description**

Validates the caller against the running core and, on success, takes a reference on the core module so the table stays valid while it is in use. Release that reference with module_put() on the returned **owner** once the API is no longer needed.

**Context**

Process context. May be called from module_init().

the API table on success, or an ERR_PTR() value: -ENODEV when the core is not ready, -EPROTO when **abi** or **size** does not match.

DNSK_ABI_PROFILE

build profile this module was compiled for

**Description**

The build profile selects the ABI-sensitive config. Every feature module stamps the profile and the macro-able knobs so dnskctl and package.py can reject a module built for a different profile. The value is recorded in modinfo as **dnsk_abi_profile**. A module built without an explicit profile carries "unknown", which does not match any real profile and so fails those comparisons.

dnsk_fs_layout - devtmpfs VFS and device layout facts

The devtmpfs port walks struct device through devices_kset and mounts its own filesystem, so these layouts are consumed by the kernel and must match the build. Each _Static_assert below pins one fact: a mismatch fails the build instead of patching device_add/device_del against a wrong view.

Why these numbers exist

The module is compiled against DDK/GKI headers but runs on the device kernel. The KMI freezes exported symbols, not the layout of internal structures: CONFIG choices (lockdep, PREEMPT_RT, KASAN, RANDSTRUCT, vendor options) and vendor patches move fields and change sizes. The port reads and writes those structures at the offsets the compiler chose, so a stale offset cannot fail safely at load time: it dereferences whatever lives at the wrong offset.

Where the numbers come from

They are measurements, not constants. The sizes and offsets were read from the android16-6.12 device BTF and are pinned by the build profile the package targets. dnsk-preflight --feature devtmpfs re-checks this same structure/field list against a live device, and dnskctl refuses insmod when it fails, so a module built for a different config is rejected both at build time and at load time.

When they change

A different KMI, CONFIG set, vendor tree, compiler or RANDSTRUCT seed changes one or more of them. They are facts about one kernel build, not fixed constants: re-measure the BTF and update this file together with the preflight table instead of editing a number to make a build pass.

What the port uses

``struct device`` (912 bytes) - ``kobj`` (0): the embedded kobject is the first member, so container_of(obj, struct device, kobj) used while walking devices_kset->list recovers the device with no adjustment. - ``devt`` (760): the device number; devices without a major are skipped, and this value is compared with kstat.rdev to decide whether an existing node belongs to this device.

``struct kobject`` (96 bytes) - ``entry`` (8): list linkage of every device in devices_kset; the initial snapshot walks it under kset.list_lock.

``struct kset`` (160 bytes) - ``list`` (0): head of that device kobject list. - ``list_lock`` (16): spinlock held while the snapshot copies the list, so a device is not published half-registered.

``struct super_block`` (1536 bytes) - ``s_root`` (104): root dentry returned by the public mount callback. - ``s_umount`` (112): rwsem taken while a second mount reconfigures the shared superblock. - ``s_active`` (180): mount counter (atomic_t) incremented for every mount, so the shared superblock is not torn down under a user.

``struct inode`` (704 bytes) - ``i_mode`` (0): file type/mode the VFS turns into kstat.mode, used to tell character from block nodes. - ``i_rdev`` (76): device number stored in the inode, the other half of that comparison. - ``i_private`` (696): set to the devtmpfs thread pointer on nodes this module created, so dev_mynode() can tell its own nodes from pre-existing ones.

``struct kstat`` (184 bytes) - ``mode`` (4): S_IFCHR/S_IFBLK test. - ``rdev`` (44): must equal device.devt for the node to be ours.

``struct vfsmount`` (64 bytes) - ``mnt_root`` (0): dentry that becomes the private root path. - ``mnt_sb`` (8): the superblock shared by every devtmpfs mount.

``struct path`` (16 bytes) - ``mnt`` (0) and ``dentry`` (8): the pair passed to vfs_getattr() for an existing node and installed as the devtmpfs thread's root and working directory.

``struct file_system_type`` (72 bytes) - ``name`` (0): "devtmpfs", matched by get_fs_type() to detect an instance that is already registered. - ``fs_flags`` (8): consulted by the VFS while the type is registered and mounted. - ``mount`` (32): public mount callback; it may be called only while the type is registered. - ``kill_sb`` (40): called by deactivate_locked_super() and may run after module exit, so it must stay kernel text (kill_litter_super); that is why both file_system_type objects are heap allocated. - ``owner`` (48): deliberately NULL so the module is not pinned by the type table.

The same set is asserted in tools/dnsk_preflight.c; keep both lists in sync.

dnsk_ns_layout - namespace syscall layout facts

This header contains no code of its own. It pins, with compile-time assertions, the size and field offsets of every kernel structure the dnsk_ns port dereferences while rewriting the namespace syscalls.

Why these numbers exist

dnsk_ns ports the Droidspaces-LKM namespace paths: it replaces syscall entries (clone, unshare, setns, getpid and related calls), walks task and pid objects to translate PIDs between namespaces, and edits ipc, user and cgroup state directly. Those paths use kernel-internal structures that the KMI does not freeze. A wrong offset does not fail at load: it silently reads or writes a neighbouring field, which is why the layout is asserted at build time instead.

Where the numbers come from

Measurements from the android16-6.12 device BTF, not ABI constants. dnsk-preflight --feature ns re-reads /sys/kernel/btf/vmlinux on the device and checks this same structure/field list before dnskctl allows insmod.

When they change

A different KMI, CONFIG set, vendor tree, compiler or RANDSTRUCT seed moves these fields. They are facts about one kernel build: re-measure and update this header together with the preflight table, never by editing a number to make a build pass.

What the port uses

``struct task_struct`` (5184 bytes) - ``pid`` (1800), ``tgid`` (1804): thread and thread-group ids in the task's active pid namespace; the port translates them for namespace-relative results. - ``real_parent`` (1816), ``parent`` (1824): biological and ptrace parent, used for reparenting and /proc parent links. - ``group_leader`` (1864): first thread of the group, for thread-group-wide operations. - ``thread_pid`` (1904): struct pid of this thread, the handle that maps a task to its number in every pid namespace. - ``nsproxy`` (2384): the namespaces the task belongs to; switching this object is what setns and unshare ultimately do. - ``signal`` (2392), ``sighand`` (2400): shared signal state and handler table, touched when a signal is delivered or accounted. - ``real_cred`` (2296), ``cred`` (2304): objective and subjective credentials; capability and namespace-owner checks read the subjective cred. - ``cgroups`` (2872), ``cg_list`` (2880): cgroup membership set pointer and the task's linkage into that set. - ``security`` (3288): LSM blob pointer, part of the task layout pinned here; the port does not interpret it. - ``comm`` (2320): task name reported by /proc. - ``fs`` (2360), ``files`` (2368): root/pwd and file table, switched during namespace setup. - ``mm`` (1672), ``active_mm`` (1680): address space used by the /proc views the port serves.

``struct nsproxy`` (72 bytes) - ``uts_ns`` (8), ``ipc_ns`` (16), ``mnt_ns`` (24), ``pid_ns_for_children`` (32), ``net_ns`` (40), ``time_ns`` (48), ``time_ns_for_children`` (56), ``cgroup_ns`` (64): one pointer per namespace type. clone/unshare copy the object and setns swaps individual members, so the port must know every slot.

``struct pid_namespace`` (136 bytes) - ``idr`` (0): allocator of pid numbers for this namespace. - ``child_reaper`` (48): task that reaps orphans in the namespace, reassigned when it exits. - ``level`` (64): nesting depth, also the index into struct pid numbers. - ``parent`` (72): parent namespace, walked towards init's view. - ``user_ns`` (80), ``ucounts`` (88): owning user namespace and the rlimit counters charged for processes in this namespace. - ``ns`` (104): ns_common embedded for nsfs identity. - ``memfd_noexec_scope`` (128): memfd no-exec policy inherited by children (max with the parent's value).

``struct ipc_namespace`` (1264 bytes) - ``ids`` (0): the SysV idr sets for semaphores, messages and shm. - ``sem_ctls`` (792): semaphore limits manipulated by semctl. - ``mq_mnt`` (960): internal mqueue mount. - ``mq_sysctls`` (1096), ``ipc_sysctls`` (1208): sysctl tables exposed through this namespace. - ``user_ns`` (1216), ``ucounts`` (1224): owning user namespace and counters for IPC resources. - ``ns`` (1240): ns_common embedded for nsfs identity.

``struct user_namespace`` (632 bytes) - ``uid_map`` (0), ``gid_map`` (64): uid/gid translation tables, read whenever an id crosses this namespace boundary. - ``parent`` (192), ``level`` (200): nesting, walked to translate towards init_user_ns. - ``ns`` (216): ns_common embedded for nsfs identity. - ``ucounts`` (488): rlimit counters owned by this namespace.

``struct cred`` (184 bytes) - ``uid`` (8), ``euid`` (24): real and effective uid, compared and mapped through cred.user_ns. - ``security`` (128): LSM blob, must follow credential changes. - ``user_ns`` (144): namespace the uids are relative to. - ``ucounts`` (152): counters charged for this credential.

``struct pid`` (112 bytes) - ``count`` (0): reference count. - ``level`` (4): highest namespace level this pid has a number in. - ``tasks`` (32): per-pid-type hash lists of tasks that use this pid.

``struct upid`` (16 bytes) - ``nr`` (0): the numeric id in that namespace. - ``ns`` (8): namespace that number belongs to.

``struct ns_common`` (24 bytes) - ``stashed`` (0): nsfs cache slot (struct dentry *) from which the namespace's nsfs path is materialised. - ``ops`` (8): namespace operations (owner, put, get). - ``inum`` (16): nsfs inode number, the number shown under /proc/pid/ns/.

``struct signal_struct`` (1120 bytes) - ``sigcnt`` (0): reference count that keeps the signal_struct alive while threads and pid references exist. - ``nr_threads`` (8): number of threads in the group. - ``thread_head`` (16): list head of the group's threads. - ``shared_pending`` (64): signals pending for the whole group.

``struct sighand_struct`` (2080 bytes) - ``siglock`` (0): protects the handler table. - ``action`` (32): installed sigaction array.

``struct cgroup`` (1984 bytes) - ``self`` (0): the cgroup's own base cgroup_subsys_state, whose ss is NULL and which points back at this cgroup. - ``flags`` (216), ``level`` (224): state flags and nesting depth. - ``subsys`` (616): per-controller css pointers. - ``nr_dying_subsys`` (680): controllers whose css is being offlined. - ``e_csets`` (736): per-controller lists of css_sets using this cgroup. - ``psi`` (1176), ``bpf`` (1184), ``freezer`` (1904): pressure, BPF attachment and freezer state of the cgroup. - ``ancestors`` (1936): parent chain, walked for subtree checks.

``struct css_set`` (456 bytes) - ``subsys`` (0): per-controller css pointers for this membership set. - ``refcount`` (64): reference count. - ``dfl_cgrp`` (80): default cgroup of the set (the v2 root, or the first v1 hierarchy the set is attached to). - ``cgrp_links`` (336): links into each cgroup's e_csets list.

The same set is asserted in tools/dnsk_preflight.c; keep both lists in sync.

dnsk_xt_layout - selecting the xtables match/target layout

CONFIG_NETFILTER_XTABLES_COMPAT is not part of the GKI KMI, but it changes struct xt_match and struct xt_target: with the option enabled the COMPAT callbacks are compiled in, the struct grows from 104 to 128 bytes, and every field after those callbacks moves by 16 bytes. The kernel walks its registered tables with the stride it was built with, so a module built for the other layout crashes xt_register_matches()/xt_register_targets() instead of failing cleanly.

Which layout is built

DNSK_XT_LAYOUT records the choice: 104 for a kernel without CONFIG_NETFILTER_XTABLES_COMPAT, 128 for stock GKI/DDK builds that keep it enabled. The value normally follows DNSK_XT_NOCOMPAT, which the build profile sets: profiles/abi/android16-6.12-xt104.json selects 104 for the device, android16-6.12-xt128.json selects 128 for stock GKI and QEMU. The profile is the source of truth, not the running uname.

Both values are measurements of one kernel build (the MTK 6.12.30 device BTF for 104, stock GKI 6.12 headers for 128), not fixed constants. A different config, vendor tree or KMI moves them, which is why the assertions below cover both branches and why unsupported values are rejected rather than guessed.

How a mismatch is caught

The module stamps the chosen value as dnsk_xt_layout=. dnskctl compares that stamp with policy.conf before insmod, and dnsk-preflight checks the device BTF with the expected value. For DNSK_XT_NOCOMPAT builds the include shim undefines CONFIG_NETFILTER_XTABLES_COMPAT before the first x_tables.h inclusion, so the module and the target kernel agree on the struct the code is compiled against.

DNSK_XT_LAYOUT

xtables struct layout the module was built for

**Description**

The value selects which xt_match/xt_target layout the assertions below accept: 104 when the target kernel was built without CONFIG_NETFILTER_XTABLES_COMPAT, 128 when it keeps the option enabled. It defaults from DNSK_XT_NOCOMPAT, which the build profile sets, and may be supplied directly by the build; either way the two #error checks below reject an inconsistent pair. The module also stamps the value as dnsk_xt_layout= so dnskctl and package.py can refuse a module built for the other layout before insmod.

The value is a property of the kernel's CONFIG, not of the KMI: a stock GKI/DDK 6.12 build is 128, while the MTK 6.12.30 device kernel is 104. Targeting another KMI or config means selecting the matching profile (and extending the build plus the preflight check for a third layout), not editing this macro.
